# 赛题3 四维评审对照（25% × 4，把证据按官方措辞对号入座）

- 版本：`four-dims-v1`，2026-11-13
- 依据：官方初赛评审 = **技术评分 100%，四维各 25%**（见 [可交 vs 可赢审计](winning-gap-audit.md) §4.2）。
- 目的：把已有证据（含 2026-11-13 新增的 Nexent 平台原生评测）按官方四维重讲，
  供 PPT / 开发设计文档 / 说明直接引用。**不新增技术口径，只做措辞对齐。**
- 纪律：每个"证据"都能用一条命令或一个文件当场复核；`设计中` 不许写成 `已完成`。

## 维度① 智能体编排与 MCP / Skill 深度集成（25%）—— 强项

官方要：MCP 协议核心机制、Skill 分层编排、检索-推理双驱动、模块解耦可扩展。

| 官方要点 | 我们的证据（可复核） | 一句话讲法 |
| --- | --- | --- |
| MCP 协议 | `urban-twin-mcp` 注册 15 工具，平台 `/api/tool/list` 15/15 全 `source=mcp`、`is_available=true` | "决策、呈现、引导、协同四类工具全部走 MCP 协议接入" |
| 检索-推理双驱动 | 主 Agent 挂 3 工具：`event_deduce`（推演）+ `evidence_locate`（溯源）+ `doc_search`（检索）；**事实只认推演，检索只管找依据** | "检索给依据、推演给结论，两者边界写死在提示词里" |
| Skill 分层编排 | 2 个 SKILL.md 已上传平台技能仓库并绑定已发布 Agent（草稿 + 发布版均 `enabled=true`） | "技能分版本、绑定可复核" |
| 模块解耦 | 主 Agent（结论）+ 协同 Agent（动作卡）分离；`collab_run` 已注册但**不抢主链路** | "裁决权在确定性内核，Agent 只翻译" |

**边界（主动说）**：技能正文当前不被主模型读取（`read_skill_md` 被有意禁用，2026-11-03 让模型读正文导致 8/8→0/8 后做的取舍）；`doc_search` 是独立检索入口，不并进主推演。

## 维度③ 算法创新性（25%）—— 需按"半自动本体构建"重新包装

官方要：低资源领域差异化原创算法、**半自动化本体构建效率优势**。

**这个维度我们一直有货，但从来没按这个口径讲过。** 重新组织如下：

| 官方措辞 | 我们的对应物 | 证据 |
| --- | --- | --- |
| 低资源（不上大模型） | 规则 + 词典基线构建本体，CPU 即可跑，不依赖大模型 | `ontology_bootstrap` / `knowledge_evolution`（改 1 格 → 2 候选 → 人工确认 → 回滚哈希逐位一致） |
| 半自动（允许人工改/反馈） | 候选抽取 → 置信度分档 → 人工确认 → 版本发布/回滚 | P3 报告 |
| 本体持续动态更新 | 事件驱动：来一个事件本体自己长一格，长出来的要人工确认才发布 | `knowledge_evolution` |
| 与行业规范对齐 | 预案→规则条目→行号溯源，与预案原文逐条对齐 | `asset_id#locator` 引用 |

**新增的"可进化"证据（2026-11-13 真机评测）**：分配策略的进化现在**在 Nexent 平台上、用平台原生 code 评估器**跑通了对比（综合得分 0.7763→1.0，见 [真机评测报告](../reports/nexent-native-eval-report.md)）——这回应了官方"进化验证基于平台原生评测机制"的要求，也是算法创新性的可复核证明。
