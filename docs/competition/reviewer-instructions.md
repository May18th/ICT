# 给评分人的一页说明（可直接转发）

> 这是一份城市内涝应急调度的智能体方案。我们在收集**真实使用者的反馈**，
> 用于验证它"越用越准"。你不需要懂技术，只要以"一个要临时做防汛调度的人"的
> 视角，看方案、打分、写一两句意见。整个过程约 5 分钟。

---

## 一、你要做什么（一句话）

看一个内涝事件的处置方案，从四个角度各打一个 1–5 分，可选地写一句"如果是你，会怎么调"。

## 二、怎么进入

- **网页（推荐）**：打开 `http://<本机地址>:8787/review`，页面上有「方案评审」表单。
  项目负责人负责起服务并把地址发给你；你只填表单，不用跑任何命令。
- **命令行（备选）**：把下面这条里的数字换成你的打分，交给项目负责人即可
  ```powershell
  uv run --locked python -m decision_poc.review_collect add --reviewer u1 --role "环境专业教师" --phase before --scores 4,3,5,4 --comment "结论清楚，但道路封闭依据可以再点到条款"
  ```

## 三、四个打分维度（1 分 = 差，5 分 = 好）

| 维度 | 你在问什么 | 打分参考 |
| --- | --- | --- |
| **准确性** | 方案给出的结论对不对？各片区该配几台泵合理吗？ | 5=都对；3=大致对但有疑问；1=明显不对 |
| **时效性** | 关键信息（缺口、封路、调拨）是不是第一时间就摆出来了？ | 5=一眼看清；3=要找一下；1=要自己拼 |
| **安全性** | 有没有把"燃气基坑""积水过阈值"这些风险点出来？ | 5=风险都说清；3=提了但不全；1=没提风险 |
| **可解释性** | 方案能不能说清"为什么这么调"？依据能不能查到原文？ | 5=每条有出处；3=有理由但没出处；1=像拍脑袋 |

## 四、两个必填项

1. **你的身份**（选一个）：同学 / 老师 / 有防汛或市政背景的人 / 其他
2. **阶段**：
   - `before`（进化前）——看的是"各片区只用本区库存、不做跨区调拨"的初版方案
   - `after`（进化后）——看的是"会跨区调拨、按风险排序"的改进版方案
   > 同一人最好 `before` 和 `after` 各评一次，这样能看出"改进了多少"。

## 五、可选项：建议分配（强烈建议填）

如果你觉得方案的分法不对，可以直接写"你觉得应该怎么分"，格式：
```
A-03=5,B-01=1
```
意思是"A-03 片区给 5 台、B-01 片区给 1 台"。
**这条建议会变成一条硬约束**：以后智能体给出的方案如果违反了你这条建议，会被自动拦下。
（这正是"人的反馈让机器变好"的证据，所以你的建议很有用。）

## 六、评分会被怎么用（请你放心）

1. 只做**汇总统计**（几个人评、平均几分、进化前后差多少），不会拿单个分数去改策略；
2. 只有你**主动填了建议分配**，那条建议才会进"校验"硬约束；
3. 记录里会注明"这是个人意见，不是部门批复"，不会把你的评分包装成官方结论。

## 七、最后提醒

- 打分是**主观感受**，没有标准答案，按第一反应填即可；
- 如果觉得"看不懂方案在说什么"，就在意见栏写"看不懂"，这也是有价值的反馈；
- 隐私：你的姓名/意见只存在本地文件里，不进代码仓库。
