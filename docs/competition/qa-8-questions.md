- 题目来源：[可交 vs 可赢审计](winning-gap-audit.md) §5 的 8 条压力测试（原样采用，未增删）。
- 话术来源：[答辩主线](answer-mainline.md)；本文件**只做三件事**：把每题压到 30 秒、把边界说出口、把证据指到能打开的位置。

  **每题都必须承认一条边界**——8 题里没有一题是"我们全都做到了"。

### 0.3 通用应答纪律（8 题都适用）

1. **先说结论，再说证据，最后说边界**——顺序反了会像在找补。
2. **承认边界的句子要主动说**，不要等评委问出来。本文件每题给的"一句话边界"就是那句话。
3. **不确定就说不确定**，宁可说 `[待核实]`，也不要给一个像样的数。
4. **跑挂了不要说"环境问题"**——直接降级并说明这是第几级（Q8）。
5. **同一场答辩里数字只出现一次写法**：缺口 2 台、902 测试、108/108、0.2264→0.0000 / 0.2182→0.0000。

## Q1 一句话说清楚：你们和别人在 Nexent 上做的 demo 有什么不同？

**评委问法**："一分钟，说清你们和别人有什么不一样？""不都是调 MCP 工具吗？"

**30 秒标准答**

> "别人是多个 Agent 商量出一个方案，我们是确定性内核出结论、Agent 只把它翻译成部门动作；冲突和先后顺序由规则裁决，方案改坏了还能逐位回滚。Agent 不参与裁决。"

**一句话边界（主动说）**：多智能体协同内核已落地，`collab_run` 也是 MCP 工具之一，协同 Agent 能在平台单跑 **2/2** 且指纹与离线逐字一致；但它**不在主推演链路里**（主 Agent 只挂两个工具），当前不让它抢主链路的裁决。

**证据引用**

| 类型 | 位置 / 命令 |
| --- | --- |
| 命令 | `python -m decision_poc.deduction --event WO-20261029-007 --as-of 2026-10-29T09:40:00+08:00`（六跳 + C1/C2/C3） |
| 命令 | `python scripts/evolution_ab.py`（A/B + 快照哈希 + 拒绝 + 回滚） |
| 文件 | `docs/reports/p6-deduction-report.md`；`docs/competition/related-work-positioning.md`（外部对照：Syed et al., PLoS One 2026，**只借方法不借数字**） |
| 现场演示点 | 公网 `https://urban-twin-demo.app.workbuddy.host/?sharecode=K4MXY6WYTS` →「运行演示」→ 下滚到「推理链路与证据」，点任一 claim 看 `asset_id#locator` |

**不能说的话**

| 不能说 | 为什么 | 改说 |
| --- | --- | --- |
| "我们多智能体协同已经跑通了/已上平台" | 协同 Agent 能在平台单跑（2/2、指纹与离线逐字一致），但**不在主推演链路**（[主线](answer-mainline.md) §1） | "协同 Agent 已在平台单跑并对上指纹；它不参与主链路裁决，我们不宣称多 Agent 协商出结论" |

## Q2 "可进化"的进化，指标是什么？谁给的反馈？反馈有几条？

**评委问法**："你的'越推越准'怎么证明不是自己跟自己比？""反馈哪来的，几条？"

**30 秒标准答**

> "指标是决策结论和我们冻结真值之间的偏差。反馈是合成真值加人工采纳或拒绝，不是真实用户评分——真实反馈目前 0 条。偏差训练从 0.2264 降到 0，留出从 0.2182 降到 0，中间还有一条候选被门禁拒了。"

**一句话边界（主动说）**：反馈是**受控合成反馈**（8 训练 + 4 留出，逐例标依据条款），人工评审是**角色扮演**，真实用户评分样本 **0**；这条不许修饰。

**证据引用**

| 类型 | 位置 / 命令 |
| --- | --- |
| 命令 | `python scripts/evolution_ab.py` → 12 用例对照表（固定 0.2237 → 进化 0.0000）+ 两臂参数快照 sha256 + 第 3 轮拒绝反例 + 回滚逐位检查 |
| 命令 | `python -m decision_poc.policy_evolution`（训练/留出偏差、轮次 3、warm start 3→1） |
| 文件 | `docs/reports/p9-policy-evolution-report.md`；`docs/competition/value-evidence.md` §3「0.2264→0.0000 是什么」 |
| 现场演示点 | 公网 `…/evolution` 页：第 1 段双会话（起点偏差 0.0000）+ 版本标签 `flood-response-v1.0→v1.1→v1.2` + 真实事件分配 |

**口径陷阱（自己先讲）**：`0.2237` 与 `0.2264` 是**两套口径**——0.2237 是全序列 A/B 的固定臂，0.2264 是训练集起点。同场出现必须加括注，否则评委会抓到"数字对不上"。

**不能说的话**

| 不能说 | 为什么 | 改说 |
| --- | --- | --- |
| "在线学习 / 持续学习 / 越跑越好" | 进化是离线门禁式，不是在线训练 | "反馈 → 归因 → 候选 → 门禁 → 版本，过门禁才发布" |
| "真实用户反馈驱动" | 真实用户样本 0 | "评分通道已就绪，样本待组织" |
| "专家已确认" | 评审是角色扮演 | "人工评审通道已跑通，参与者是团队扮演" |
| "12 个用例全对所以效果真实" | 用例是冻结合成 ground truth | "12 例是受控评测集，不是真实回流" |

## Q3 不用 LLM 能不能跑？能跑的话 LLM 的价值是什么？

**评委问法**："把模型拔了还剩下什么？""那你这算 Agent 吗？"

**30 秒标准答**

> "能跑，演示默认就跑确定性路径。LLM 负责理解事件和表达结论，优先级和冲突裁决永远在确定性推演手里。平台真机上能看出这层分工：证据不出进程时 3 次全错（opt-2×2、opt-1×1）；把证据原文和职责边界补齐后复测 3/3 命中参照 opt-3——这 3/3 证明的是服从性，不是模型能独立算出同样的排序。"

**一句话边界（主动说）**：平台演示链路现挂 **DeepSeek-Chat**（原 openPangu-2.0-Pro 于 2026-11-06 欠费停服后切换，主/协同 Agent 重发布 v19 / v7）；本地决策节点 A/B 与公网单端点同样走 DeepSeek，密钥只走环境变量。

**证据引用**

| 类型 | 位置 / 命令 |
| --- | --- |

## Q6 策略错了怎么办？

**评委问法**："万一进化出一个更差的策略呢？""能退回去吗？"

**30 秒标准答**

> "坏策略进不了发布：门禁不过就不生效，这次就有一条候选被拒。已经发布但被判变坏的，可以回滚到上一版本，回滚后偏差逐位还原到 0.2264，不是近似值；版本标签可追溯。"

**一句话边界（主动说）**：门禁的留出集只有 **4 例**，统计强度有限；人工评审是角色扮演；回滚是**同库版本回退**，不是线上灰度。

**证据引用**

| 类型 | 位置 / 命令 |
| --- | --- |
| 命令 | `python scripts/evolution_ab.py` → 输出里"第 3 轮拒绝反例"与"回滚逐位检查"两段 |
| 命令 | `python -m decision_poc.policy_evolution --report docs/reports/p9-policy-evolution-report.md` |

**宁可这样讲**：回滚"逐位还原"是因为我们**对比了位级哈希/浮点逐位相等**，不是"看起来回去了"——这句话本身就是可验证的（脚本会打印检查结果）。

| "回滚大概能回到之前水平" | 是逐位还原，不是"大概" | "偏差逐位还原到 0.2264" |

## Q7 这套东西的业务收益是多少？怎么算的？

**评委问法**："省了多少人力？少跑多少趟？""给我个百分比。"

**30 秒标准答**

> "目前只有单点估算，没有实测对照。能给三个可复算的中间量：跨区调拨本身要 40 分钟，所以缺口早发现最多提前 40 分钟；错序绕行多 3040 米、慢 5.1 分钟；缺口 2 台。省多少人力我们没测，不给百分比。"

**一句话边界（主动说·必须一字不改地说）**：**40 分钟是上限，不是平均值**；人工协同 vs 智能体辅助的对照实验（3 人各计时一次）**尚未做**；没有交通流量数据，**不折算车次与金额**。

**证据引用**

| 类型 | 位置 / 命令 |
| --- | --- |
| 命令 | `python -m decision_poc.counterfactual --case CF1` → J-01↔J-02 由 820 m/1.2 min 变 3860 m/6.3 min（多 3040 m / 慢 5.1 min） |
| 命令 | `python -m decision_poc.counterfactual --case CF2` → 库存 6→2 时的取舍（优先保 A-03 的依据） |
| 数据 | `samples/assets/urban/resource_inventory.csv` → `RES-PUMP-M-B01` 的 `capacity_note`："跨区调用需 40 分钟" |
| 文件 | `docs/competition/value-evidence.md` §3（三套换算逐一写明；§2 对照表**明确标注"推算/待实测"，不得进 PPT 主表**） |
| 现场演示点 | 现场跑 CF1，一边出数一边说"这是中间量，不是收益" |

**换算逻辑一句话**（被追问"40 分钟怎么来的"时）：
> "缺口发现得越早，调拨就能越早开始；人工是到场盘点后才发现，我们是推演时就报；所以收益上限等于两次发现时刻之差，也就是调拨所需的 40 分钟。"

**不能说的话**

| 不能说 | 为什么 | 改说 |
| --- | --- | --- |
| "效率提升 X% / 减少 XX 次出车 / 节省 XX 万元" | 这三个都没有对照实验与流量数据 | "只给可复算中间量，不给百分比" |
| "平均提前 40 分钟" | 40 分钟是上限 | "最多提前 40 分钟（上限）" |
| "每天 X 车次通过" | 无交通流量数据，乘出来就是编的 | "单车次代价可复算；总量缺流量数据，不宣称" |
| "已经在真实单位试用" | 没有 | "场景与数据接口按真实台账字段设计，未实地部署" |
