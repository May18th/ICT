## 3 背景与问题

暴雨内涝不是单一部门事件：道路积水 → 封路 → 地下燃气管线施工受阻 → 抢修与抽排争抢同一批移动泵，
责任部门横跨排水、道路、交通、燃气、供电。现实中的三个痛点：

1. **结论不可追溯**：一句"建议先封路"背后可能是三份预案、两张台账，但没人能当场指出是哪一条；
2. **冲突被"综合判断"抹平**：职责空白（泵站无运维主体）与权限交叉（道路/交通都能封路）在汇报里消失；
3. **决策不会进化**：同一类事件再次发生，还是靠人从头推一遍，上次的教训没有沉淀。

## 4 方案总览

```
异构资产（表/文/图）
   └─ 数据资产层：统一标识、校验和、定位符、版本、有效期、可见性
        └─ 认知层：解析 / 切片 / 表格标准化 / 实体关系候选 / 本体半自动构建（人工确认 + 回滚）
             └─ 语义层：城市孪生对象 + 语义关系（带时态、版本、权限），查询强制 as_of + snapshot_hash
                  └─ 推演层：六跳（现象→对象→责任→冲突→资源→动作）+ 三类冲突 + 二次风险
                       └─ 溯源层：claim 引用闸门 + 哈希链账本 + 变更传播影响分析
                            └─ 决策层：稀缺资源分配策略（有版本、可评测、可回滚）
                                 └─ 进化层：偏差归因 → 候选策略 → 评测门禁 → 采纳/拒绝 → 记忆沉淀
                                      └─ 编排层：Nexent Agent + MCP 工具（12 个）+ Skill（2 个）
```

## 6 核心机制与创新点

### 创新点一：事件驱动的城市语义层自动演化
新数据进场 → 抽取候选三元组 → 差异比对（新增/冲突/失效）→ 进化提案（**自带影响评估**：受影响实体、规则、
历史结论数）→ 人工确认 → 发布 `kb-vX.Y.Z` → 一键回滚。实测：改 1 个单元格只产生 2 条候选（修复前 18 条），
回滚后快照哈希逐位一致。

### 创新点二：面向跨部门协同的因果推演与反事实
六跳固定（跳数固定才能算"路径正确率"），规则是数据（32 条规则逐条校验原文行号，来源不符拒载）。
输出可解释因果链；反事实 = 对同一 DAG 干预后重放：CF1 封路使 J-01↔J-02 由 820 m/1.2 分钟变为
3860 m/6.3 分钟；CF2 库存 6→2 时缺口 2→6 台并给出优先保障 A-03 的依据；CF3 暴露等级 orange→red。

### 创新点三：推理结果的可验证数据血缘与影响分析
三层反向索引 `asset → triple → claim → decision`；数据一改，系统说出"哪 3 条历史推演、1 条处置建议
已不可信"，并只重算最小受影响子集。漏报率 0、重算范围比 < 30%。

### 创新点四：稀缺资源的决策策略受控进化（赛题 3 的"进化"落点）
- 决策对象：跨片区抽排资源分配（推演只回答"缺多少台"，不回答"先给谁"）；
- 反馈信号：冻结 ground truth（8 训练 + 4 留出，逐例标注依据条款）+ 人工评审结论；
- 进化机制：偏差归因 → 候选参数 → 训练集选优 → 门禁（留出集不退化 + 不违反评审）→ 采纳/拒绝 → 版本标签与回滚；
- 实测：训练偏差 **0.2264 → 0.0000**、留出 **0.2182 → 0.0000**；3 轮（采纳 2 / 拒绝 1）；
  真实事件分配由 `A-03 4 台 / B-01 2 台` 变为 `A-03 6 台 / B-01 0 台`（跨区 40 分钟时延来自台账）；
- 持续性与可信：分层记忆 warm start（第二次会话起点偏差 0.0000、轮次 3→1）、人工评审通道
  （评审用例偏差 0.1171→0，不满足即拒）、策略标签 `flood-response-v1.0 → v1.1 → v1.2`、回滚可复原。
