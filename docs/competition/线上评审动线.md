# 线上评审动线（评委 3 分钟版）

> 这一页是给**没有现场讲解**的评审准备的：打开链接后照着走三步，不需要任何领域知识，也不需要输入任何编号。
> 全部内容都可在浏览器里当场点开核对，没有"只有作者才能演示"的环节。

---

## 三步走完（约 3 分钟）

### 第一步｜看清这是什么（40 秒）

打开门户首页 → 点第一块 **① 这是什么**

你会看到一张街区大屏：积水范围、封路位置、三座泵站的运行状态、各部门的处置动作按时间轴排开。

**要点**：范围只有成都兴华路片区约 3 公里。路名与设施编号为示意，不是测绘数据。
我们只做一个片区，是因为"换片区要重做台账、预案条款与服务带宽度"——方案能迁移，标定不能迁移。

---

### 第二步｜看它怎么推的、凭什么信（90 秒）

回到首页 → 点 **③ 凭什么信**（进入证据工作台）

对话区下方有三个现成的问法按钮（「这地方积水了，该谁去处理？」「先封路还是先开泵？」「兴华路泵站设计流量多少？」），**点一个就行，不用打字**。它会返回六跳推演：

```
雨情定级 → 受影响设施 → 责任部门 → 跨部门冲突 → 资源缺口 → 处置动作
```

**关键动作**：随便点答案里任意一条结论，右侧会展开**台账原文的那一行**。

这就是本作品的主张：不是"模型说应该这样"，而是"每个结论都能回到某一行字"。
结论由本地规则引擎算出，模型只负责把它讲成中文——所以"说的"和"算的"是同一件事。

---

### 第三步｜它会错吗（50 秒）

打开首页 → 点 **④ 它会错吗**（跳到 `/limits`：三组同题对照 + 已量化的偏差）

这里有三种对照，都可以当场复现：

| 对照 | 结果 | 说明 |
| --- | --- | --- |
| 正常配置（给了工具） | **八项全过**，4 个不同事件各一次 | 主链路真机实测 |
| 去掉全部工具，其余完全不变 | **只对上 2 项**（会话 #136、#200 两次复跑都是 2/8） | 能对上的只剩"步骤说全""编号回填"——这两项不查台账也能凑 |
| 无工具 + 要求凭经验出方案 | 编出一个**格式完全正确的假指纹** | 所以验收不能只看"有没有这个字段"，必须逐位比对 |

第三种最有价值：它说明"看起来专业"和"真的算过"是两件事，而我们的验收只认后者。

## 主动说明的三条边界

评审如果只看亮点，容易高估；以下三条我们主动写出来：

1. **只有一个片区、四个事件**（WO-20261029-007/009/013/021）。不是全市系统。
2. **不是实时系统**。没有 SCADA、没有控制回路，是离线快照 + 情景推演。严格说是 Digital Shadow，不是实时数字孪生。
3. **"省人力/省时间"未实测**。业务价值有可复算的数字（调拨提前量、绕行代价、缺口台数），但"人工协同要多久"没有做过对照计时，所以不写。

| 想核什么 | 怎么核 |
| --- | --- |
