## 6 结论（只陈述本用例集上成立的差异）

- **六跳完整率**：0.00% → 63.64%；增量集中在 `semantic_only` → `single_skill`（+63.64%）。
- **安全处理率**：0.00% → 100.00%；增量集中在 `semantic_only` → `single_skill`（+87.50%）。
- **范围与资源覆盖率**：0.00% → 63.64%；增量集中在 `single_skill` → `multi_skill`（+63.64%）。
- **引用完整率**：0.00% → 63.64%；增量集中在 `multi_skill` → `full_audited`（+63.64%）。
- **可审计率**：0.00% → 63.64%；增量集中在 `multi_skill` → `full_audited`（+63.64%）。
- **末两档之间**（`multi_skill` → `full_audited`）：引用完整率、可审计率 变化，六跳完整率、安全处理率、范围与资源覆盖率 逐位不变。
- 归因只看阶梯上的**增量方向**；某档增量为 0 就写 0，不为了叙事把它包装成"显著提升"。

## 7 与外部研究的表述边界

- 本报告是**受控评测环境**下的组件归因，不是真实市政部署测量；
- `rules_only` 是阈值规则基线（不含语义层/推演/审计），不代表本仓库的历史版本；
- 统计量**全部确定性**：没有随机种子、没有多次重复实验，p 值与 leave-one-out 范围换机器重跑逐位一致；不宣称"多运行重复实验"；
- 引用外部论文的消融结论时，只借方法（五档阶梯、同口径指标、威胁到有效性自省），
  不引用其效果量——其数字来自合成蒙特卡洛仿真；
- 本仓库不宣称区块链：审计层是 append-only 哈希链日志，见 P4 设计红线。
