# 业务价值实测方案（把「待测」变成数字）

- 目标：把 `value-evidence.md` §2 里两行 **待测** 换成实测值——「首次形成完整处置方案时间」和「跨部门确认次数」。
- 现状：这两行一直是估算（人工 20–40 分钟、智能体 3–5 分钟）。**估算不能当证据用**，被问「你们计过时吗」时答不上来。
- 成本：3 人 × 90 分钟，一个下午做完，不需要任何外部数据。

---

## 1 能测什么，不能测什么

这一节决定了结论能写到多硬，必须先定死。

| 环节 | 能不能测 | 说明 |
|---|---|---|
| 拿到工单 → 定位积水位置、判深度 | **能真测** | 台账在纸上/在页面里，都是真的 |
| 判断谁负责、调几台泵、封哪条路 | **能真测** | 这是决策内核的输出，可对照 |
| 形成一份可交付的方案初稿 | **能真测** | 计时到「写完最后一笔」 |
| 跨部门电话确认、等回复 | **不能测** | 不能在办公室真的打电话骚扰协作单位 |
| 现场到场、抽排作业 | **不能测** | 没有真实事件 |

所以本方案测出来的指标，**正确名称是「方案成形时间」**，不是「处置完成时间」。
汇报时必须用前者。说成「处置时间缩短 X%」就是越界，会被追问「你们真封过路吗」。

跨部门确认次数可以数：方案里落到几个部门、几次交接，是**从产物里数的**，不是估的。

---

## 2 实验设计

同一份工单，两组人，同样任务，分别计时。**两组用的原始资料完全相同**，只是取用方式不同。

| | A 组（人工/现状） | B 组（工具） |
|---|---|---|
| 给的资料 | 打印件：路网表、设施台账、管线台账、工单、部门职责表、历史记录 | 同一套数据的页面版（`/map2d` + `/workbench`） |
| 任务 | 写出一页处置要点：积水位置与深度 / 责任单位 / 抽排资源（几台、从哪调）/ 是否封路、封哪段 / 三条主要风险 | 同左 |
| 计时起点 | 拿到打印件的第一秒 | 打开页面的第一秒 |
| 计时终点 | 写完最后一条风险 | 同左 |
| 允许的操作 | 翻纸、查表、写 | 点页面、查证据、写 |
| 禁止 | 用手机搜、问旁边人、用 AI | 同左 |

**轮换**：A、B 两组都做一遍（交叉设计），否则「谁手快」会污染结论。3 个人 → 每人做 2 次（A 一次、B 一次），共 6 次测量。

工单固定用 `WO-20261029-007`（兴华路，30 cm）——这是唯一有完整证据链的事件，换别的对不上。

---

## 3 计时口径（提前说死，避免事后争议）

- **只计「有产出」的时间**：看资料、判断、写字都算；上厕所、接电话不算，按分钟扣。
- **卡住超过 2 分钟没人推进**，记一次「卡点」，写在备注里——这比总时长更有说服力。
- **不算打字速度差异**：B 组可以直接口述让记录员写，A 组同样。写字不是被测对象。
- 用手机秒表，起止各报一次时间，记录员当场写下。

## 4 记录表

每测一次填一行，存 `docs/reports/value-measurement.csv`（模板已建，直接追加）。

| 字段 | 含义 |
|---|---|
| `run_id` | A1/A2/B1…（组别 + 序号） |
| `participant` | 参与者代号（P1/P2/P3，不写姓名） |
| `group` | `manual` / `tool` |
| `started_at` / `ended_at` | 起止时刻 `HH:MM:SS` |
| `minutes` | 耗时（分钟，保留一位小数） |
| `depts_touched` | 方案里落到几个部门 |
| `handoffs` | 几次交接（一个部门做两件事算一次） |
| `stuck_count` | 卡点次数 |
| `depth_cm` | 该参与者写下的积水深度 |
| `pumps` | 写下的抽排资源（台数） |
| `sealed` | 是否判对封路（`yes`/`no`/`partial`） |
| `note` | 卡在哪、为什么 |

**判对的标准**用 `answer-mainline.md` 的口径：深度 30 cm、缺口 2 台、封兴华路全幅。写错了不算「快」，要在备注里记下来——**准确率比速度更重要**，一组又快又错等于没做。

## 5 换算与回填

```
方案成形时间缩短 = (manual 中位数 − tool 中位数) / manual 中位数
```

- 用**中位数**不用平均值：3 个人 6 次测量，平均值会被一次异常拉偏。
- 同时报**准确率**：`判对项数 / 总判对项`。
- 结论写成一句话，例如：
  > 「方案成形时间：人工组中位数 24 分钟，工具组中位数 4.5 分钟；工具组 6 项判断全部正确，人工组 4/6（深度与调拨台数各有 1 人写错）。」

回填到 `value-evidence.md` §2 的「首次形成完整处置方案时间」行，把「待测」改成实测值 + 样本量（`n=3 人 / 6 次`）。

## 6 如果工具组没有明显更快

必须照实写，不能调参凑数。三种可能及处置：

| 现象 | 说明什么 | 怎么写 |
|---|---|---|
| 工具组只快一点（<20%） | 资料本来就不难查，价值在别处（准确率、可追溯） | 主指标换成「判断准确率」和「证据可追溯率」，速度作为次要指标 |
| 工具组更慢 | 页面有认知负担（要先学怎么读） | 这是**真发现**，写进「下一步」：降低首次使用门槛 |
| 两组都很快 | 任务太简单，测不出差异 | 换更复杂的工单（多片区、资源缺口更大），重测 |

最后一种要提前准备：备选工单 `WO-20261029-009`（基坑+燃气，涉及两个部门）。
