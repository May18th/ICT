## 1. 反事实怎么算：干预输入 → 重建 → 重放 → 取 diff

一句话：**不改代码，改世界，然后用同一套规则重跑一遍，比结论。**

| 手段 | 改什么 | 用在哪 |
| --- | --- | --- |
| `data_patch` | 数据集某一行某一列（库存数量、完工时间） | CF2、CF3 |
| `rule_patch` | 规则的一个参数（处置顺序 `then.order`） | CF1 |

为什么不是"改逻辑再跑"：改代码的两条分支不再共享同一套规则，diff 出来的差异就不再是"干预造成的"，而是"代码差异造成的"，无法复核。

落地细节：

- 数据补丁在临时目录里改副本，`shutil.copytree` → 改 CSV → 用副本重建 runtime；**样本数据一个字节不动**（有测试比对 sha256）。
- 补丁必须唯一命中一行，命中 0 行或 2 行直接报错——"改到了不该改的行"比"没改"更危险。
- 规则补丁写临时 JSON，仍然走 `verify_rules` 的原文行校验，所以改完规则的出处依然可查。
- 分支跑 `persist=False`，不写溯源账本：反事实是推演，不是对外结论。

## 2. 三个用例的实测

### CF1：若先封路再隔离风险源

```
基线:   动作 9 项 / 冲突 3 项 / 缺口 1 / 可发布 是
反事实: 动作 9 项 / 冲突 3 项 / 缺口 1 / 可发布 是
  顺序: 封闭积水路段全幅… 第 3 → 第 2 位
  顺序: 封路由 ORG-ROAD 与 ORG-TRAFFIC 联合发布… 第 4 → 第 3 位
  顺序: 隔离风险源… 第 2 → 第 4 位
道路可通行性:
  R-101 兴华路: 封闭
  R-102 建设大道: 可通行
  R-103 民生街: 受施工影响
  R-104 环城北路: 可通行
  R-105 兴华支路: 受施工影响
结论: 封路由第 3 位提前到第 2 位，隔离风险源由第 2 位后移到第 4 位；封路后可通行道路为
      建设大道、环城北路；受限道路 兴华路(封闭)、民生街(施工)、兴华支路(施工)。
无法计算的部分:
  ! 抢修到场时间：数据集不含路网拓扑与行驶速度字段，无法计算通行时间变化
  ! 绕行里程：road_network 只有单条长度，没有路段连接关系，无法算路径长度
```

**这里刻意没有写"燃气抢修会慢 15 分钟"。** 没有路网拓扑和车速，这句话既算不出来也验不了，答辩时一被追问就崩。能算的是：顺序变了多少位、封路后哪些道路还可通行。可通行集合是从道路表和施工计划算出来的——`R-103` 名义上是被指定的绕行路，本身却在占道施工，这正是二次风险的来源。

### CF2：若抽水泵只有 2 台

```
基线:   动作 9 项 / 缺口 1 / 库存 6
反事实: 动作 9 项 / 缺口 5 / 库存 2
  缺口: RES-PUMP-M +4 台
片区优先级:
  A-03 (WO-20261029-007) 深度 30cm 封路 是 危险源 有 需 7 台 / 缺口 5
  B-01 (WO-20261029-011) 深度 18cm 封路 否 危险源 无 需 2 台 / 缺口 0
  · A-03 积水 30cm，已过封路阈值（阈值 25cm）
  · A-03 受影响范围含燃气/电力管线，存在次生风险
  · B-01 积水 18cm，未过阈值，且无次生危险源
  · RES-PUMP-M-B01: 单台 400 m3/h，跨区调用需 40 分钟
结论: 抽水泵 6 台 → 2 台，缺口 1 台 → 5 台；A-03 需 7 台、B-01 需 2 台，优先保障 A-03…
```

**优先级不是写死的，是跑出来的。** 两个片区各跑一遍完整推演，比较四个量：是否过封路阈值、是否含次生危险源、积水深度、动作条数。A-03 两项命中，B-01 全不命中。

跨区代价直接引用 `resource_inventory.csv` 的 `capacity_note`（"跨区调用需 40 分钟"），附证据定位，不是凭经验补一句。

### CF3：若 CP-2026-041 延期一天

```
基线:   动作 9 项 / 缺口 1
反事实: 动作 9 项 / 缺口 1
差异: 无（结论层面完全一致）
  （数据版本已变，但结论未变）
结论: 工期顺延一天未改变任何推演结论：规则条件里没有任何工期字段（已检查
      start_at,end_at,reported_at,issued_at,valid_from,valid_to,duration_days），
      工期变化不参与任何一跳判定。该问题在当前知识下不可判定——需要补规则与逐日气象，
      而不是补一段结论。
```

**这个结果看上去像"没做成"，其实是做对了。**

系统扫了一遍 26 条规则的 `when` 条件，确认没有任何日期字段参与判定，于是如实回答"当前知识回答不了这个问题"，并点名缺什么。如果这里编一句"开挖面暴露跨越降雨窗口，风险等级上调"，那就是标准的幻觉：既没有规则支撑，也没有逐日气象数据。

顺带修了一个语义错误：第一版把"延期"实现成开工推迟一天，结果今日基坑直接不存在，推演结论大变（少 3 个动作、危险源消失、缺口 -1）。那是"推迟"，不是"延期"。现在只顺延完工时间，开工不变。

## 3. 接进 MCP：第 8 个工具

```
counterfactual_run(case_id, event_id, as_of, caller_labels)
```

放进 MCP 而不是只留 Python 接口，因为 Demo 要现场回答"如果……会怎样"；只留进程内函数，P7 只能演假交互。

一个关键判断：**基线本身算不出来时不回"空差异"。** 空差异会被读成"没有影响"，这与"算不出来"是两件事，但两者在展示层长得一模一样。

这个判断放在核心 `run_counterfactual()` 里（抛 `CounterfactualUnavailable`），不是只在 MCP 层挡一道。原因是第一版只加在 MCP 上，CLI 走同一路径时照样返回"差异：无（结论层面完全一致）"——同一条安全规则两个入口两套行为，等于没做。

现在的行为：

| 情形 | 结果 |
| --- | --- |
| 基线 `PERMISSION_DENIED`（如 `ORG-ROAD` 看不到燃气规程） | 拒绝比较，MCP 回 `PERMISSION_DENIED`，CLI 打印后退出码 2 |
| 基线 `EVIDENCE_INSUFFICIENT`（如审计闸门拒绝） | 拒绝比较：不可发布的结论不足以做基线 |
| 未知用例 | `NOT_FOUND`，回可选值 `["CF1","CF2","CF3"]` |
| 重放过程异常 | `EVIDENCE_INSUFFICIENT` |

注意区分：基线**降级**（如缺深度导致 `partial`）仍允许比较——那是有效的、只是不完整的基线，正好是反事实该处理的场景；只有 `error` 才拒绝。

`skill_manifest()` 升到 1.1，新增 `standalone_tools`：反事实不是链路中的一跳，而是对已发布结论的追问，所以不进 `SKILL_ORDER`，由编排层在拿到基线结论后直接调用。绑定表里的工具名仍由测试对着 `UrbanToolkit.tools()` 校验。

## 4. 不变量（都有测试）

| 不变量 | 断言 |
| --- | --- |
| 样本数据不被修改 | CF2/CF3 跑完，`resource_inventory.csv`、`construction_plans.csv` 的 sha256 不变 |
| 反事实不落账 | 传入空账本，跑完 `records() == []` |

| 干预必须唯一命中 | 命中 0 行 / 未知列 / 未知规则 → 抛错 |

## 5. 结论只由算出来的量拼装

`_verdict()` 里的每个数字都来自 diff、分支汇总或数据表，没有任何一句"通常会……"。这条规则不是为了好看：**一旦允许一句解释性文字，它就会成为整套可验证性里唯一无法验证的部分**，而答辩恰恰专挑这种句子问。

三个用例的 `uncomputable` 字段把所有算不出来的部分显式列出，和结论一起返回。

## 6. 遗留（P8 之前）

1. **CF3 需要补两条东西**：规则集缺"工期与降雨窗口重叠"的判据；气象数据只有小时级单条预警，没有逐日预报。补齐后 CF3 才能给出"风险等级上调"这样的结论——现在给不了，也不该给。
2. **CF1 需要路网拓扑**：现在只能回答"哪些路可通行"，回答不了"到场时间后移多少"。要答第二问，`road_network.csv` 得补路段连接关系与限速字段。
3. **CF2 的低洼点规则口径**：`RULE-RES-LOWSPOT-PUMPS` 计的是"其他片区"的低洼点，所以 B-01 自己的 2 台需求其实是替 A-03 备的。两片区同时独立推演时总量不可直接相加——这是规则口径问题，不是代码问题，P8 评测前应统一。

## 7. 复现

```powershell
$env:PYTHONPATH = "src"

# 三个用例一起看
uv run --locked python -m decision_poc.counterfactual --case all

# 单个用例 / 原始 JSON
uv run --locked python -m decision_poc.counterfactual --case CF2
uv run --locked python -m decision_poc.counterfactual --case CF3 --json

# 越权身份：拒绝比较，退出码 2
uv run --locked python -m decision_poc.counterfactual --case CF1 --caller-labels ORG-ROAD
# -> [CF1] 拒绝：基线不可比较：resource_check 返回 PERMISSION_DENIED
```
