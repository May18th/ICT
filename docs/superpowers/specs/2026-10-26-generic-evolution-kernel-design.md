# 通用可进化决策内核设计

## 目标

在不绑定行业、不接生产系统和不开发完整 UI 的前提下，验证一个可复用的决策智能体内核：它能接收通用请求，收集模拟证据，生成结构化决策，经过校验和模拟审批后执行模拟动作，记录反馈，并在评测通过时发布策略候选版本，失败时保持旧版本或回滚。

## 非目标

- 不固定任何行业领域、业务流程、最终评价指标或数据模型。
- 不接入真实 Nexent 服务、真实模型、生产数据库、真实运维工具或凭据。
- 不实现完整业务 UI、真实身份认证、真实权限系统或真实副作用执行。
- 不允许智能体直接修改自身代码、任意 Prompt 或核心安全规则。

## 技术边界

- **LangGraph**：唯一的状态流和节点编排器，负责顺序、分支、终止和可序列化状态。
- **Pydantic AI**：执行结构化决策节点；使用 Pydantic Schema 约束输入和输出。
- **确定性 Python 规则**：负责字段一致性、证据要求、风险审批、预算/重试限制和版本发布门禁。
- **模拟工具**：只返回结构化工具信封，不连接外部系统。
- **LangChain Core**：只提供演示/评测 `Runnable` 适配，不建立第二套 Agent Loop。

## 通用流程

```text
DecisionRequest
  → 模拟证据工具
  → Pydantic AI 生成 DecisionOutput
  → 相关性、证据和风险校验
  → 模拟审批
  → 模拟执行工具（仅审批通过）
  → FeedbackRecord
  → 生成 PolicyVersion candidate
  → EvaluationReport 门禁
  → promote 或 retain/rollback
```

## 可进化定义

可进化对象只包含通用策略参数和版本元数据。反馈可以生成候选版本，但候选版本必须经过外部评测报告；评测失败不改变 active version，回滚只能指向已知版本。所有版本操作应进入历史记录。

## 可靠性要求

- 工具结果统一包含 `status`、`data`、`error`、`stats`、`context`。
- 工具失败需要区分可重试与不可重试，并记录尝试次数。
- 高风险或缺少审批的请求不得执行模拟动作。
- 图状态只保存 JSON 兼容值，便于检查点、回放和跨边界传输。
- 所有终止路径有明确 `termination_reason`，并保留 trace。

## 验收边界

本阶段只验收协议、流程分支、失败恢复、版本门禁、回滚、序列化和技术基线记录；真实模型质量、行业效果和最终比赛指标留到赛题方向确定后单独设计。
