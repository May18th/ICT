# 知识治理与 RAG 证据层设计

## 背景与意图

当前 PoC 已验证通用决策请求、模拟证据、结构化决策、审批、执行、反馈和策略进化。下一阶段增加知识治理与检索增强的抽象，使项目能够验证：结构良好的企业知识是否能提供更稳定、可追溯的决策证据。

这里的 Wiki 与 RAG 不是竞争方案：Wiki 表示知识组织和治理方式，RAG 表示把外部知识检索并注入任务上下文的工程链路。两者通过统一证据契约连接到现有 LangGraph 决策流。

## 目标

- 定义与具体 Wiki 产品无关的知识条目和治理元数据。
- 将当前模拟证据工具抽象为可替换的证据提供器。
- 保证检索结果携带来源、版本、有效期和权限过滤信息。
- 在决策前执行证据新鲜度、来源一致性和冲突提示校验。
- 增加检索质量评测维度，但不提前确定行业指标。
- 保持离线、可复现、无真实外部副作用的 PoC 边界。

## 非目标

- 不接入 Notion、Confluence、语雀、华为知识库或其他真实 Wiki。
- 不绑定 Milvus、Elasticsearch、FAISS、云向量库或具体 Embedding 服务。
- 不在当前阶段确定分块算法、向量模型或最终召回阈值。
- 不把知识库改造成新的 Agent Loop；LangGraph 仍是唯一流程编排器。
- 不把知识治理元数据误当作领域业务字段。

## 分层架构

```text
知识条目与治理元数据
    ↓ 过滤：权限 / 状态 / 有效期 / 版本
证据提供器 EvidenceProvider
    ↓ 关键词、向量、混合检索或结构化查询（当前使用模拟实现）
证据结果 ToolResult[EvidenceItem]
    ↓ 来源、版本、内容和新鲜度校验
LangGraph 决策状态流
    ↓
Pydantic AI 结构化决策 → 审批 → 模拟执行 → 反馈与评测进化
```

知识治理层负责“知识是什么、由谁维护、何时有效、谁能看”；RAG 层负责“本次任务取哪些知识、按什么顺序返回”；决策层只消费经过契约化的证据，不直接依赖 Wiki 或检索实现。

## 通用契约方向

### KnowledgeItem

建议包含以下通用字段：

- `knowledge_id`：稳定唯一标识；
- `title`、`content`：可展示和可检索内容；
- `topic_path`：主题层级路径；
- `source`、`version`：来源和版本；
- `status`：`draft`、`published`、`deprecated`；
- `owner`：维护责任人或责任组；
- `valid_from`、`valid_until`：有效期；
- `visibility`：抽象权限标签；
- `relations`：相关条目的稳定 ID 列表。

### EvidenceQuery

建议包含：`request_id`、查询文本、主题过滤、权限上下文、时间点、返回数量上限和检索模式。查询契约不暴露底层向量库参数。

### EvidenceProvider

提供同步和异步入口，返回现有 `ToolResult` 信封。`data.items` 中的每个证据必须能映射回 `KnowledgeItem` 的来源和版本，失败时使用结构化错误码，不返回空字符串伪装成功。

## 流程变化

现有“模拟证据工具”保留为默认离线提供器。后续流程调整为：

```text
DecisionRequest
  → EvidenceQuery
  → EvidenceProvider
  → 权限 / 有效期 / 来源 / 版本 / 冲突校验
  → Pydantic AI DecisionOutput
  → 现有审批、模拟执行、反馈和策略版本流程
```

没有合格证据时，流程必须返回明确终止原因；不得让模型自行补齐缺失事实。检索失败、权限过滤为空和证据过期应使用可区分的错误码或终止原因。发现相互冲突的知识时，默认暂停自动决策和执行，输出冲突来源、版本和有效期，交给有权限的人工审核者决定继续、拒绝或补充证据。

## 评测方向

在现有技术基线之上增加可选的检索评测字段：

- `retrieval_hit`：是否返回预期证据；
- `source_match`：决策引用是否匹配返回来源和版本；
- `freshness_ok`：是否使用有效期内版本；
- `permission_safe`：是否泄露不可见条目；
- `conflict_detected`：冲突知识是否被识别并暂停自动执行；
- `evidence_sufficiency`：证据是否足以支持当前决策。

这些指标先用于技术回归和 bad case 记录，不宣称行业效果，也不替代最终比赛指标。

## 受控进化边界

反馈可以推动检索排序参数或决策策略生成候选版本，但候选版本必须经过冻结评测集验证。知识内容本身不能被智能体自动改写或发布；知识变更与策略变更分开审计，避免把错误检索结果直接变成长期知识。

## 验收标准

- 不依赖外部服务即可用模拟知识条目和模拟提供器运行。
- 证据结果继续满足现有 `ToolResult` 结构和 JSON 序列化要求。
- 过期、越权、来源不一致、版本不一致和冲突证据均有可测试的失败路径。
- 冲突证据不得直接进入模拟执行；人工批准只表示授权用户明确选择继续，不由模型自行推断。
- 真实 Wiki、向量库和行业 Schema 仍可作为后续适配层接入，不改变 LangGraph 主流程契约。
- 现有测试保持通过，并新增检索契约、权限/有效期过滤和引用一致性测试。

## 实现决策

- 第一阶段使用内存知识条目和确定性模拟检索，保证测试可复现。
- 先定义协议和失败状态，再讨论切片、Embedding、向量库和具体 Wiki 连接器。
- 领域主题确定前，`topic_path`、权限标签和评测集只使用通用示例，不写行业流程。
