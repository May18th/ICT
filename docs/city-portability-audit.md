# 城市可移植性审计：换一个城市要改什么

> 目的：回答「你们这套只能做成都吗」。方法是查代码里的城市常量，不是再搭一座城做演示。
> 重跑：`python scripts/audit_city_constants.py`（加 `--all` 连字符串行一起打印）。

## 结论

1. **决策链路不含城市常量**：`chain.py`、`deduction.py`、`allocation.py`、`counterfactual.py`、
   `evidence_resolver.py` 里没有任何一处把片区号、路名、设施号写进判断或默认值——全部从台账读。
2. **资产 scope 本来就是多级的**：片区（`A-03`）14 项、城市（`CD-CITY`）2 项、路段（`R-101`）2 项、
   设施（`DF-PS-01`）1 项。证据引用形如 `A-03/road_network/v1.1#row:4`，前缀是**资产所属**的 scope，
   不是这一行数据的 district——B-01 的路也挂在那份 A-03 资产下，所以前缀正确。
3. **换城市剩下要动的是 4 个标定值**，都在定量层脚本里，且必须由新城自己的实测撑起来。

扫描结果：全仓 279 行命中城市常量，其中**只有 4 行是真正的代码常量**（全部在定量层脚本），
`src/decision_poc/` 里一行都没有——其余是注释、资产登记文案和界面文字。

| 位置 | 写死的值 | 换城市后的后果 |

这四个数**不是 bug**：它们是这座城市的标定结果，照抄到别的城市才是错的。
换句话说，「换城市」真正的成本不在代码，在**重新标定**——这也正是当前最该补的一块：
用 2020-08-11 的定级记录反推产流系数，出一张「实测定级 vs 模型算深」偏差表，
既回答「模型哪来的」，又顺手把换城市最重的一块补掉。

## 怎么复核

```bash
python scripts/audit_city_constants.py          # 摘要 + 代码行明细
python scripts/audit_city_constants.py --all    # 连字符串行一起看
```

脚本判据只有一条：城市常量出现在**字符串之外**（常量、比较、默认值）才算风险，
出现在注释和文案里不算。它区分不了「用作字典键的字符串」和「给人看的字符串」，
所以 `_BUILTIN_CRITICAL_CM` 这类是人工复核后单独处理的——机器扫一遍，人再看一遍。

## 一句话讲法

> 六步推演、冲突判定、调拨分配三块不含任何城市常量，换城市就是换一套台账；
> 要重做的是四个标定值和一批文案。资产按片区/城市/路段/设施四级登记，
> 跨片区靠调拨关系连——这是我们这一版有意收窄的边界，不是没做。
