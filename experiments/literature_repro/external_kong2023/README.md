# 外部数据方法对照（非成都，不构成本项目验证）

> **这个目录不产出任何本项目的结果。** 数据来自外部城市的道路积水观测，与成都片区管网不是同一对象，
> 这里的任何输出都不得用于说明本项目的精度、效果或适用性，也不进作品材料。
>
> 它只回答一个方法结构问题：**纯雨量输入的回归代理，能不能跨点位预测水位、能不能外推退水？**
> 答案是不能。这个结论支撑本项目选择带状态量的简化演进，而不是拿外部数据当成绩单。

## 为什么保留

本项目在该数据上做过一次对照，得到两条与选型有关的判断：

1. **跨点位不可迁移**：同一点位内雨量与水位关系稳定，换成另一条路就基本失效。缺的是点位物理属性
   （汇水面积、坡度、管网容量），不是模型容量。这也解释了文献里为什么必须先有管网模型生成标签。
2. **退水段无法由雨量外推**：雨停后输入趋零、预测也趋零，实测仍在缓退。退水靠蓄量释放，
   纯雨量输入在结构上表达不了。

具体数值不入库，重跑即可重建。保留代码是因为：评估口径（自拟合 / 随机点留出 / 跨路留出 /
时间外推四档）将来换成成都本地数据时可以直接复用。

## 评估口径（可复用部分）

输入只用雨量类特征（当前雨强、过去 5/15/30/60/120 min 累积、累积总量、历时），**不含水位历史值**：
水位自相关极强，一旦放进滞后水位，NSE 会虚高到接近 1，测的就不是降雨驱动。

四档切分必须一起看，单独任何一个都会误导：

| 切分 | 作用 |
|---|---|
| 逐路自拟合 | 上界。同序列进出，任何平滑回归都能拿到高值，不是精度 |
| 随机点留出 | 插值。留出点被邻居包围，偏高 |
| 跨路留出 | 泛化。这才对应"换一个点位还能不能用" |
| 后段外推 | 退水。雨停后能否外推 |

四档放在一起才能区分「特征没用」「关系是每路一套」「退水缺状态量」三种情况。
